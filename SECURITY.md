# Security policy

## Private reports

Use [GitHub private vulnerability reports](https://github.com/Chelis-Lang/buoy/security/advisories/new).
Do not submit security details through public issues, discussions, or pull requests.

Include the affected commit, command, reproduction steps, and expected impact.
Remove credentials, private keys, and unrelated personal data from all report material.
Send exploit details only through the private report form.

Maintainers must enable private reports during the approved public-visibility change.
The form can remain unavailable while the repository is private.
Repository administrators can use the [GitHub configuration instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
Until the form is available, do not place vulnerability details in any public channel.

## Maintenance scope

The current `main` branch is the security maintenance target.
Include the exact source revision when a report concerns an older export.
This policy sets no response deadline.
A source release does not establish a security audit or production readiness.
