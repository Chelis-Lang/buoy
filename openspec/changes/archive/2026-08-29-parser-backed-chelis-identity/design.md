## Context

The Chelis integration shipped with a total comment-record grammar but lexical anchoring: records attach to the next `def`/`type` line, and item identity digests that line's text. Nautilus adopted it live and proved the pipeline, and its adoption recorded three follow-ups: report-exposed revisions, consumer-package exposure of the command, and an advisory CLI. Chelis maintains generated tree-sitter grammars for Surf and Deep in its own tree (`grammars/tree-sitter-chelis-surf`), regenerated by `tree-sitter generate` and inventoried as intentional derivations. Chelis `v0.18.5` (`fc3232ffe085d15b213bb7457b69a22063a200b9`) is the revision Nautilus currently pins.

## Goals / Non-Goals

**Goals:**

- Give Surf records parser-canonical identity equal in kind to the Rust adapter's: node-derived bytes, node spans, loud parse failures.
- Vendor the pinned generated parser with a registered derivation and a fail-closed drift check, using the integration's own derivation semantics.
- Close the three recorded Nautilus follow-ups in the same change so a host adoption needs no out-of-band tooling.

**Non-Goals:**

- Deep (`.dp`) parsing; the Deep dialect keeps lexical anchoring until its grammar is adopted separately.
- Changing the `chelis:provenance/v1` record comment grammar or the `chelis/surf-declaration/v1` item kind.
- Blocking policy, Chelis-repo edits, or the Nautilus re-pin (follow-on change).

## Decisions

### Vendor the generated parser, not the generator

`crates/chelis-surf-sitter/vendor/` receives the exact generated sources from Chelis `fc3232ff`: `parser.c`, `scanner.cc`, `grammar.json`, `node-types.json`. A registration records the source repository, revision, per-file digests, and the `tree-sitter generate` tool identity; a blocking test recomputes the vendored digests and fails on drift. Alternative: fetch or regenerate at build time. Rejected: both break the offline realization and import an unpinned toolchain.

### One binding crate, one build script

`chelis-surf-sitter` is the only workspace crate with a build script; it compiles the vendored C/C++ through the pinned `cc` crate and exposes the tree-sitter `Language` plus typed node helpers. `chelis-provenance` stays build-script-free and consumes the safe API. The two new dependencies (`tree-sitter`, `cc`) enter `deny.toml` review with exact version pins.

### Parser-backed anchoring, unchanged record grammar

Records stay comment blocks. Extraction parses the file once; a record anchors to the first top-level declaration node whose start byte follows the record block, with nothing but blank lines between. Identity: `ParsedItemIdentity.semantic_bytes` = the declaration node's canonical source bytes; span = the node's byte range. Comments and non-declaration nodes stay nonnormative through the same total classification. A tree-sitter `ERROR` or `MISSING` node in a selected file produces `CHELIS-PROV-PARSE-ERROR` and fails the static exit class.

### Frozen identity bump with reingestion

The descriptor moves to `chelis-surf-syntax/v2` with parser version `0.18.5+grammar.fc3232ff`. Identities derived under the lexical scheme are not migrated; schema-v3 rules apply: source reingestion, no legacy reader, no mapping. The Nautilus re-pin performs that reingestion downstream.

### Reports carry revisions

`chelis-static-report/v2` adds, per object class, the identity digest, and for atoms the revision digest, in canonical sorted order. This retires the helper-crate bootstrap that Nautilus needed and is the single biggest adoption-cost reduction available.

### Package and CLI exposure

`nix/consumer-package-v1.nix` adds `--package chelis-provenance` to the build flags so the realized package installs both binaries; the package-contract checks assert the new binary and its usage exit class. The CLI gains an `advisory` subcommand that renders the existing advisory report deterministically.

## Risks / Trade-offs

- **C/C++ enters the workspace build** → confined to one crate, compiled from vendored pinned sources through pinned `cc`; the clean-sandbox realization proves it builds offline.
- **Grammar version skew against future Chelis releases** → the derivation registration names the exact revision; re-pinning is one reviewed vendor refresh with the drift check as the tripwire.
- **Report schema bump breaks report consumers** → goldens and the Nautilus gate scripts parse JSON keys additively; v2 only adds fields, and the schema string change makes the bump explicit.
- **External scanner (`scanner.cc`) behavior differences across platforms** → covered by the existing cross-root determinism assertions plus parse fixtures in the frozen pack.

## Migration Plan

1. Pin and vendor the grammar with its derivation registration and drift check.
2. Land the binding crate with parse fixtures, including error-node totality.
3. Switch Surf extraction to parser-backed anchoring and identity; bump the frozen identities; regenerate crate fixtures and goldens.
4. Ship report v2, the advisory subcommand, and the consumer-package exposure.
5. Run the sanctioned assurance regeneration and the full `devenv test` oracle.
6. Follow on in Nautilus: re-pin, reingest, drop the helper bootstrap notes from its trust document.

Rollback before merge is deleting the crate and reverting the extraction module; after publication, returning to lexical identity would itself require reingestion under a new syntax schema.

## Open Questions
